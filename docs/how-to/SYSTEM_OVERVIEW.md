# System Overview: MongoDB RAG Agent

This guide provides a high-level overview of how the entire MongoDB RAG Agent system works, how all components connect, and how data flows from document upload to answer generation. This is your starting point for understanding the complete system.

> **Visual Diagram**: A comprehensive system architecture diagram is available in Excalidraw. The diagram shows the complete end-to-end flow from project creation through document ingestion, session creation, question processing, and answer generation, including all database collections and their relationships.

## Introduction

The MongoDB RAG Agent is an intelligent question-answering system that helps you find answers in your documents. It combines document storage, intelligent search, and artificial intelligence to provide accurate, cited answers to your questions.

## What This System Does

At its core, the system:

1. **Stores Documents**: Safely stores your documents with all their information
2. **Makes Documents Searchable**: Breaks documents into searchable pieces
3. **Answers Questions**: Finds relevant information and generates answers
4. **Organizes Work**: Organizes everything into projects and sessions
5. **Tracks Progress**: Tracks your work and maintains history

## Key Concepts

### Projects

**What They Are**: Containers that organize all work for a specific client, case, or matter.

**What They Contain**:
- Documents related to the project
- Sessions conducted for the project
- Company information
- Project status and workflow

**Why They Matter**: Projects help you keep everything organized and ensure questions are answered using the right documents.

### Sessions

**What They Are**: Question-and-answer conversations within a project.

**What They Contain**:
- Questions you ask
- Answers generated by the system
- Citations to source documents
- Review and rating information

**Why They Matter**: Sessions organize your Q&A work and track progress through consultation rounds.

### Documents

**What They Are**: Files you upload (PDFs, Word documents, etc.) that contain information.

**What Happens to Them**:
- Content is extracted and stored
- Important information is identified and saved
- Documents are broken into searchable pieces
- Mathematical representations are created for intelligent search

**Why They Matter**: Documents are the source of all answers - the system finds information in your documents to answer questions.

### Questions and Answers

**What They Are**: Questions you ask and answers the system generates.

**How They Work**:
- Questions are analyzed and sometimes broken into sub-questions
- The system searches documents and previous Q&A history
- Answers are generated using artificial intelligence
- Answers include citations to source documents

**Why They Matter**: This is the core functionality - getting accurate, cited answers to your questions.

## System Architecture Overview

### High-Level Flow

The system follows this overall flow:

1. **Setup Phase**:
   - Create a project
   - Upload documents to the project
   - Documents are processed and stored

2. **Question Phase**:
   - Create a session within the project
   - Ask questions in the session
   - System searches documents and generates answers

3. **Review Phase**:
   - Review answers
   - Edit answers if needed (Senior users)
   - Rate answers and mark outcomes

4. **Completion Phase**:
   - Export sessions
   - Create follow-up sessions if needed
   - Complete projects

### Component Overview

#### Document Storage

- **Documents Collection**: Stores complete documents with all metadata
- **Chunks Collection**: Stores searchable pieces of documents
- **Purpose**: Makes documents searchable and retrievable

#### Project Management

- **Projects Collection**: Stores project information and status
- **Purpose**: Organizes work by client or case

#### Session Management

- **Sessions Collection**: Stores session information and metadata
- **Q&A Pairs Collection**: Stores questions and answers (Senior users)
- **Purpose**: Organizes Q&A work and tracks progress

#### Search and Retrieval

- **Semantic Search**: Finds documents by meaning
- **Text Search**: Finds documents by keywords
- **Hybrid Search**: Combines both approaches for best results
- **Purpose**: Finds relevant information to answer questions

#### Answer Generation

- **AI Synthesis**: Combines information from multiple sources
- **Citation Generation**: Links answers to source documents
- **Purpose**: Creates comprehensive, accurate answers

## Data Flow: From Upload to Answer

### Step 1: Document Upload

**What Happens**:
- User uploads a document to a project
- System receives the file

**Where Data Goes**:
- File is prepared for processing

### Step 2: Document Processing

**What Happens**:
- Content is extracted from the document
- Metadata is identified and extracted
- Document is broken into chunks
- Embeddings are generated for each chunk

**Where Data Goes**:
- Complete document → Documents Collection
- Chunks with embeddings → Chunks Collection

### Step 3: Question Processing

**What Happens**:
- User asks questions in a session
- Questions are extracted and analyzed
- Complex questions are decomposed into sub-questions

**Where Data Goes**:
- Questions are prepared for search

### Step 4: Document Search

**What Happens**:
- System searches Documents and Chunks collections
- Uses both semantic and text search
- Finds top relevant document sections
- Optionally searches Q&A history

**Where Data Goes**:
- Search results are collected
- Results are ranked by relevance

### Step 5: Answer Generation

**What Happens**:
- System combines search results
- Uses AI to synthesize information
- Generates comprehensive answer
- Creates citations to source documents

**Where Data Goes**:
- Answer is generated
- Citations are linked

### Step 6: Answer Storage (Senior Users)

**What Happens**:
- Answer is saved as Q&A pair
- Citations are stored
- Question embedding is saved for future searches

**Where Data Goes**:
- Q&A pair → Q&A Pairs Collection
- Linked to session

### Step 7: Answer Review (Senior Users)

**What Happens**:
- User reviews answer
- User can edit answer if needed
- User can rate answer
- User can mark outcome status

**Where Data Goes**:
- Updates → Q&A Pairs Collection

## How Components Connect

### Projects → Documents

- Projects contain documents
- Documents are linked to projects via `project_id`
- Project-scoped searches prioritize project documents

### Projects → Sessions

- Projects contain sessions
- Sessions are linked to projects via `project_id`
- Sessions inherit project context

### Sessions → Q&A Pairs

- Sessions contain Q&A pairs
- Q&A pairs are linked to sessions via `session_id`
- Q&A pairs track question order within sessions

### Documents → Chunks

- Documents contain chunks
- Chunks are linked to documents via `document_id`
- Chunks include document metadata for filtering

### Q&A History → Future Answers

- Previous Q&A pairs inform future answers
- Follow-up sessions reference previous Q&A pairs
- Similar questions find previous answers

## Key Features Explained

### Project Scoping

**What It Is**: Limiting searches to documents within a specific project.

**How It Works**: When you search within a project's session, the system prioritizes documents uploaded to that project.

**Why It Matters**: Ensures answers come from relevant documents for the specific project.

### Question Decomposition

**What It Is**: Breaking complex questions into simpler sub-questions.

**How It Works**: System analyzes questions and identifies when they ask about multiple topics, then creates sub-questions.

**Why It Matters**: Ensures comprehensive answers by addressing all aspects of complex questions.

### Hybrid Search

**What It Is**: Combining semantic and text search for best results.

**How It Works**: System performs both types of search simultaneously and merges results, prioritizing documents found in both.

**Why It Matters**: Provides more accurate and comprehensive search results than either method alone.

### Citation Generation

**What It Is**: Linking answers to source documents.

**How It Works**: System tracks which documents were used to generate each part of an answer and creates citations.

**Why It Matters**: Allows you to verify answers and find original source material.

### Follow-Up Sessions

**What It Is**: New sessions that build on previous sessions.

**How It Works**: Follow-up sessions include context from previous Q&A pairs, allowing the system to build on earlier work.

**Why It Matters**: Enables iterative refinement and building comprehensive answers over multiple rounds.

## User Roles and Permissions

### Junior Users

**Capabilities**:
- Ask questions
- Receive answers
- View citations

**Limitations**:
- Answers are not saved
- Cannot edit answers
- Cannot rate answers

**Use Case**: Exploration and learning

### Senior Users

**Capabilities**:
- Ask questions
- Receive answers
- Save Q&A pairs
- Edit answers
- Rate answers
- Mark outcomes
- Export sessions

**Use Case**: Official consultations and deliverables

## Data Storage Overview

### What Gets Stored

#### Documents Collection

- Complete document content
- All extracted metadata
- Document identification information
- Business outcome information

#### Chunks Collection

- Searchable text pieces
- Embeddings for semantic search
- Links to parent documents
- Document metadata for filtering

#### Projects Collection

- Project names and information
- Company information
- Project stages and history
- Timestamps

#### Sessions Collection

- Session names and metadata
- User roles
- Project links
- Status and outcomes
- Company information

#### Q&A Pairs Collection

- Questions and answers
- Citations
- Ratings and reviews
- Outcome status
- Session links
- Question embeddings

### Data Relationships

- **Projects** contain **Documents** and **Sessions**
- **Sessions** contain **Q&A Pairs**
- **Documents** contain **Chunks**
- **Q&A Pairs** can reference **Documents** (via citations)
- **Follow-up Sessions** reference **Previous Sessions**

## Expected Workflow

### Typical Project Workflow

1. **Create Project**: Start a new project with company information
2. **Upload Documents**: Add all relevant documents to the project
3. **Create Session**: Create a Q&A session for the project
4. **Ask Questions**: Ask questions and receive answers
5. **Review Answers**: Review, edit, and rate answers (Senior users)
6. **Create Follow-Up**: Create follow-up sessions if needed
7. **Export Results**: Export sessions when complete
8. **Complete Project**: Mark project as finalized

### Typical Session Workflow

1. **Create Session**: Create session with appropriate role
2. **Ask Questions**: Enter questions to be answered
3. **Review Answers**: Review generated answers and citations
4. **Edit Answers**: Edit answers if needed (Senior users)
5. **Rate Answers**: Rate answers as good or bad (Senior users)
6. **Mark Outcomes**: Mark outcome status for Q&A pairs
7. **Export Session**: Export session with all Q&A pairs

## Troubleshooting Overview

### Common Issues

- **Documents Not Found**: Ensure documents are uploaded and ingested
- **Answers Incomplete**: Check that relevant documents are uploaded
- **Answers Not Saved**: Verify you're using a Senior session
- **Project Not Found**: Ensure project is created and loaded
- **Session Not Found**: Verify session is created and active
