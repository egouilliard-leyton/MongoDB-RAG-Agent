# CR: Add Stats Command to CLI

**Created:** 2026-01-26
**Status:** Draft
**Scope:** Small
**Priority:** P3-Low

## Summary

Add a `stats` CLI command that displays system statistics (document count, chunk count, database info) to help with debugging and monitoring.

## Problem Statement

Currently, users have no way to quickly check the state of the MongoDB database from within the CLI. They need to either:
- Query MongoDB directly using external tools
- Write one-off scripts to check counts
- Infer database state from search results

This makes debugging and monitoring unnecessarily difficult, especially when troubleshooting ingestion issues or verifying system state.

## Current Behavior

The CLI supports three special commands:
- `info` - Shows LLM/embedding configuration
- `clear` - Clears the screen
- `exit`/`quit`/`q` - Exits the CLI

There is no command to view database statistics.

## Desired Behavior

Users can type `stats` in the CLI to see:
- Total number of documents in the database
- Total number of chunks in the database
- Database name and collection names
- Optional: Index information (if available)

The output should be formatted in a Rich panel similar to the existing `info` command for consistency.

## Affected Areas

| File/Module | Type of Change | Description |
|-------------|----------------|-------------|
| `src/cli.py` | Modify | Add `stats` command handler in the main loop |

## Implementation Approach

Add a new command handler in the CLI's main loop (around line 422, after the `info` command handler) that:

1. Loads settings to get MongoDB connection details
2. Creates an AgentDependencies instance to connect to MongoDB
3. Queries document and chunk counts using Motor's `count_documents()`
4. Displays results in a Rich panel
5. Properly cleans up the database connection

### Key Changes

1. **Add stats command handler**: Insert new `elif` block in the command handling section
2. **MongoDB queries**: Use async `count_documents({})` on both collections
3. **Rich formatting**: Format output using `Panel` with cyan/bold styling for consistency
4. **Error handling**: Wrap MongoDB operations in try/except to handle connection failures gracefully

## Dependencies

- No new dependencies required
- Uses existing `AgentDependencies` class
- Uses existing `load_settings()` function
- Uses Rich library (already imported)

## Breaking Changes

None expected. This is a purely additive change that adds a new optional command.

## Implementation Notes

**Code location**: src/cli.py lines ~422-426 (after `info` command, before `clear` command)

**Example implementation structure**:
```python
elif user_input.lower() == 'stats':
    settings = load_settings()
    agent_deps = AgentDependencies()
    try:
        await agent_deps.initialize()
        doc_count = await agent_deps.db[settings.mongodb_collection_documents].count_documents({})
        chunk_count = await agent_deps.db[settings.mongodb_collection_chunks].count_documents({})

        console.print(Panel(
            f"[cyan]Database:[/cyan] {settings.mongodb_database}\n"
            f"[cyan]Documents:[/cyan] {doc_count:,}\n"
            f"[cyan]Chunks:[/cyan] {chunk_count:,}\n"
            f"[cyan]Document Collection:[/cyan] {settings.mongodb_collection_documents}\n"
            f"[cyan]Chunk Collection:[/cyan] {settings.mongodb_collection_chunks}",
            title="Database Statistics",
            border_style="cyan"
        ))
    except Exception as e:
        console.print(f"[red]Error fetching stats: {e}[/red]")
    finally:
        await agent_deps.cleanup()
    continue
```

**Important considerations**:
- Use `count_documents({})` not `estimated_document_count()` for accuracy
- Always call `agent_deps.cleanup()` in finally block to prevent connection leaks
- Use `:,` format specifier to add thousand separators (e.g., "1,234")
- Match the styling of existing `info` command (cyan color, panel borders)
- Add `continue` at the end to skip normal conversation processing
